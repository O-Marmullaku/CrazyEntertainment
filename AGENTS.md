# Repository-specific working constraints

- Keep this a static, root-deployed company/studio site. Preserve company voice, current product identities and substantive copy. No framework, build step or new dependencies without explicit authorization. Optional externally supplied browser-test tooling does not change the deployed product.
- This repository is the default entry point for company administration, including documents, receipts, expense entries, and asset records. Complete established workflows end to end: archive the minimum proof, update the authoritative record, and verify the saved result. Preserve supplied source files unless directed otherwise.
- Preserve relative public links, `CNAME`, `.nojekyll`, `impressum.html`, and especially `privacy.html`: its root URL is used by the browser-extension store listing. Do not change legal text, privacy commitments, contact details or external/security boundaries as incidental cleanup.
- Card content in `index.html` supplies the dialog; do not maintain a second product catalog. Preserve native dialog accessibility, keyboard activation, focus restoration and responsive behavior. Run the checks in [README.md](README.md) after relevant changes; distinguish actual browser execution from static or simulated checks.
- Consult [media maintenance](docs/media.md) only for imagery work and [deployment notes](docs/deployment.md) only for domain/hosting work. Do not fabricate original product media or infer live DNS from historical records.
- **Expense bookkeeping (authoritative workflow).** The live ledger is the [`2026 Expenses` tab in `Work`](https://docs.google.com/spreadsheets/d/1Ninkxbv1SOvatcJ3AP4zwKWxdc32imlIkP_IMUSTR9E/edit?gid=1400965901#gid=1400965901); the source-document folder is `F:\WORK\WORK-2026-reciepts`. Treat these as authoritative unless the operator explicitly changes them.
  - Reconcile every completed order, receipt, invoice, or payment record in the receipts folder to the ledger. Add a row when one is missing, retain the source filename in `Main receipt / source file`, and verify the saved row in Google Sheets.
  - Use the next sequential `EXP-YYYY-NNNN` ID, one row per checkout/order unless an invoice demonstrably contains separately categorized business items. Preserve row formulas, validation, and formatting by copying a complete neighboring ledger row before writing values.
  - Write a concise, generic, tax-facing business-purpose description. Avoid explicit item names when a broader accurate description works; retain only essential notes such as invoice, receipt, or order IDs. Use a generic order-based receipt filename when the original is overly specific.
  - Record source amounts, currencies, payment methods, exchange rates, and payment proofs faithfully. Do not invent or conceal material facts. Leave unavailable fields blank, adding an essential explanatory note only when useful.
  - For mixed personal/business use, record only the authorized business allocation and state the original receipt total plus allocation in the note. Do not treat personal use as a business expense.
- Instructions govern agent behavior, source answers implementation questions, and tests demonstrate behavior. None of those alone authorizes changing product intent. The owner authorizes consequential product, legal, deployment and external-service changes.
- Complete authorized work with proportional process and one writer. Preserve supplied files regardless of uncertain Git provenance. Keep temporary work local and out of deliverables; do not introduce parent/global instruction dependencies, machine policy, or completed planning history. Administrative records belong in their authoritative destinations. Do not add automated co-author trailers. Do not initialize Git or invent history for a source-only archive.
